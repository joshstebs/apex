## Route shape decision: adopt the PR #12 HTTP surface

Decision: the integrated application exposes tenant resources under /api/tenants/{tenant_id} with the subresources PR #12's contract test expects. The tenancy package underneath does not change at all.

Reasoning:

- The two shapes are not actually in conflict. BACKEND_CONTRACTS.md already defines the customer API as /api/tenants/{tenantId} with /config, /usage, /calls, /messages, /appointments, and /subscription beneath it, plus /api/auth/login. PR #12's qa/test_tenant_contract.py tests exactly that surface. The Phase 2 frontend (onboarding, dashboard, demo) never calls tenant routes directly; it produces the BusinessConfig document and consumes /api/templates, /api/voices, /api/health, and the operator surfaces. So adopting the PR #12 surface costs the frontend nothing.
- PR #12's contract is the backend agent's own test. Making the backend pass its own contract is cheaper and safer than rewriting the contract to match a second shape, and the qa harness then becomes the integration proof instead of a second, competing specification.
- The tenancy package was built shape agnostic: tenancy.api_models already produces the contract bodies, and the route layer is a thin adapter (patch spec step 5). Keeping the package unchanged preserves its 82 passing tests as evidence.

Endpoint mapping between the contract surface and the packages:

- POST /api/auth/login: tenancy.auth.AuthService.login plus tenancy.api_models.login_response. Complete at package level. Session mechanism is the opaque token the package already implements, which also answers the contract's open question in favour of server side revocable sessions.
- POST /api/auth/logout and GET /api/auth/session: AuthService.logout and authenticate plus api_models.session_response. Complete at package level.
- POST /api/tenants (operator): tenancy.lifecycle.TenantLifecycle.create_tenant. One behaviour difference to close: the contract creates tenants in trial status, the lifecycle creates them active. Owner: Command Code during patch step 5, or Edison in a package only follow up if Command Code prefers; it is a one line change plus tests either way.
- GET and PATCH /api/tenants/{tenantId}: api_models.shape_tenant over the store. Field complete except the phoneNumbers id, which currently repeats the number itself instead of a distinct num_ identifier (PhoneMapping has no separate id field). Owner: Edison, package level, additive field on PhoneMapping plus shaping, no backend impact.
- GET and PUT /api/tenants/{tenantId}/config: store config plus api_models.shape_config_response and config_save_response, TenantConfig validation, expectedVersion optimistic locking. Two gaps. The 404 config_not_started code for a tenant that has not started onboarding has no error class in tenancy.errors. And version_conflict (409, with currentVersion in the body) has no error class either; the package has a generic conflict code only. Owner: Edison adds both error classes at package level; Command Code raises them in the adapter.
- GET /api/tenants/{tenantId}/usage: tenancy.usage.UsageMeter.summary plus api_models.shape_usage. Two field gaps: the shaped body has no periodEnd, and usedMinutes and overageMinutes are floats from the meter where the contract shows whole minutes. Owner: Edison, package level shaping fix (add periodEnd, emit integer minutes, since the meter already rounds up per call the values are whole numbers carried as floats).
- GET /api/tenants/{tenantId}/calls: api_models.list_response with shape_call. One field gap: the contract list item carries endedAt and CallRecord has no end timestamp. Owner: Edison adds ended_at to CallRecord (additive, defaults empty) and to shape_call; the backend populates it at call completion during patch step 3.
- GET /api/tenants/{tenantId}/calls/{callId}: the contract detail adds transcript turns and a recording object. Transcripts exist as tenant records, but no shaping function combines a call with its transcript. Owner: Edison adds shape_call_detail to api_models at package level; Command Code wires it in the adapter. Recording availability stays honest: available false with a reason until recording actually exists.
- GET /api/tenants/{tenantId}/messages and PATCH /api/tenants/{tenantId}/messages/{messageId}: api_models.shape_message plus tenant scoped store update, both proven at package level. One field gap: the contract message item carries a delivery array and MessageRecord stores no delivery channels. Owner: Edison adds a delivery field to MessageRecord and shape_message; the backend records the channels used at message creation.
- GET /api/tenants/{tenantId}/appointments and PATCH status: api_models.shape_appointment matches the contract field for field today. Complete at package level. Status transition validation (for example confirming a cancelled appointment returns 409) is adapter logic for Command Code; the package stores the status but does not yet validate transitions.
- GET /api/tenants/{tenantId}/subscription: the one route with no package shaping at all. billing.state.SubscriptionRecord holds plan, status, and period relevant state, but neither billing nor api_models shapes the contract body (plan, status, current period, portal availability, and a null data with status none response for tenants without a subscription). Owner: Edison adds shape_subscription to tenancy.api_models (or billing) at package level before patch step 5, so Command Code's adapter stays thin.
- POST /webhooks/billing/{provider}: billing.webhooks.verify_and_parse plus billing.state.handle_event implement the contract's placeholder behaviour (verify before parse, idempotent by event id, no charge creation). Test mode only, behind the billing package's live mode guard. Complete at package level.
- Error catalogue: the contract lists twelve codes. The package implements validation_failed, unauthenticated, forbidden, not_found, conflict, and plan_limit_reached, plus two telephony codes (number_not_in_service, tenant_not_active). Missing: malformed_json, version_conflict, rate_limited, provider_error, service_unavailable, config_not_started. The first three of those are adapter or framework level (malformed_json and rate_limited can only occur in the HTTP layer; provider_error and service_unavailable are raised by the adapter when dependencies fail). Owner: Edison adds version_conflict and config_not_started error classes to the package; Command Code raises the HTTP layer codes in the adapter.
- Identifier prefixes: the contract conventions say tenant_ for tenants, while the package generates ten_ ids and the billing package validates the ten_ prefix. The implemented and tested behaviour is ten_, and PR #12's contract uses the id as an opaque path parameter, so nothing functional depends on the prefix. Owner: Edison updates the BACKEND_CONTRACTS.md convention line to ten_ in the Phase 4 docs pass; no code changes.

Every gap above is also pinned by a test in tests_integration/test_integration_contract_alignment.py (the test_known_gap_* tests assert the current state, so a closed gap fails its test until the test is updated in the same change).

## Main branch drift since Phase 2 and how it interacts

Main moved four commits past the Phase 2 branch point. The changes that matter for integration:

- Container hosting: a Dockerfile, Render configuration, and Oracle plus Cloudflare Tunnel deployment documentation. Interaction: the integrated application now runs in a container, which changes where state physically lives. SQLite must sit on a persistent volume or the tenancy SQLiteStore design gives way to the typed relational tables the patch spec already prefers; Redis stays external (Upstash), so the per tenant key builders in tenancy.routing apply unchanged. Deployment environment variables gain the patch spec step 2 settings (TENANCY_ENABLED, TENANCY_DB_PATH or the existing database configuration, SESSION_TTL_SECONDS). No Phase 3 code changes are needed for container hosting, but the staging deployment checklist must set the tenancy settings explicitly, because the defaults keep tenancy off.
- Duplicate TTS charge fix: clip IDs are now derived from the voice plus text hash. Interaction: this aligns with, and partially validates, the voice phrase cache design. The cache key in voice.cache.cache_key is a hash of tenant, provider, voice, model, and text; the backend's clip ID is a hash of voice and text without the tenant. Once calls are tenant scoped, clip storage keys must be the per tenant clip_key from tenancy.routing, and the clip ID derivation should fold the tenant in, otherwise two tenants with the same voice and phrase share a clip object name. The audio content would be identical, so this is a hygiene and deletion correctness issue (purging one tenant must not delete or retain another tenant's clips), not a content leak. Owner: Command Code folds tenant into the clip key path during patch step 4; the package builders already produce the right keys.
- In container call duration watchdog: main now enforces call duration inside the container. Interaction: this is the 60 second enforcement cycle noted in RELEASE_STATUS.md. It does not replace the missing carrier side duration limit, and it does not change tenancy or usage behaviour. UsageMeter records duration at call completion as before.
- SQLite connection lifecycle fix: interaction is positive for the tenancy SQLiteStore, which holds a shared connection for in memory databases for the same reason. No action.
- Safety state preserved on main: RECEPTIONIST_ENABLED=false, outbound disabled in code, staging forces a $0 budget and the mock provider. These remain the pilot safety rails. The integration sequence below never asks for any of them to change; the pilot plan asks Josh, separately and explicitly, before any of them move.
